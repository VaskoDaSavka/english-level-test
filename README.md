# English Level Check — готовый сайт диагностики для 9 класса

**28 заданий:** 26 вопросов с автоматической проверкой (10 Grammar, 6 Vocabulary, 5 Reading, 5 Listening) + 2 письменных задания, которые проверяет преподаватель. Адаптивный дизайн, баллы, объяснение ошибок, Firestore для хранения работ, закрытый кабинет преподавателя, экспорт CSV.

## Что входит в архив

- `index.html` — страница ученика.
- `admin.html` — кабинет преподавателя (вход по email и паролю).
- `student.js`, `admin.js`, `questions.js`, `style.css` — логика, задания, оформление.
- `firebase-config.js` — сюда необходимо вставить настройки Firebase.
- `firestore.rules` — **обязательно** установить в Firebase до передачи ссылки ученикам.
- `README.md` — эта инструкция.

## 1. Создайте Firebase-проект

1. Откройте https://console.firebase.google.com и нажмите **Add project**. Создайте проект (например, `english-level-school`).
2. На странице проекта добавьте **Web app** (значок `</>`). Назовите приложение и получите объект `firebaseConfig`.
3. Откройте `firebase-config.js` в редакторе и замените значения `REPLACE_ME` на значения из Firebase Console. **Не вставляйте** секретные ключи сервисного аккаунта или private key. Firebase Web API key не является секретом, безопасность обеспечивает Firestore Rules.
4. Откройте **Build → Authentication → Sign-in method**. Включите два метода: **Anonymous** (ученики), **Email/Password** (преподаватель).
5. В **Authentication → Users** создайте преподавателю учётную запись с email и надёжным паролем (**Add user**). Скопируйте его **User UID** (не email).
6. Откройте **Build → Firestore Database → Create database**. Создайте базу в подходящем регионе. Для реальных данных учеников используйте осознанный выбор региона и предварительно проверьте применимые требования по защите персональных данных.
7. Откройте `firestore.rules`, замените `TEACHER_UID` на UID преподавателя из шага 5. В **Firestore Database → Rules** вставьте полный текст файла и нажмите **Publish**. **Не используйте Test mode или `allow read, write: if true` для настоящих работ учеников.**
8. В **Authentication → Settings → Authorized domains** добавьте домен вашего сайта GitHub Pages, например `username.github.io`, если его нет в списке. Укажите только домен, без `https://` и без пути репозитория.

## 2. Опубликуйте на GitHub Pages

1. Создайте репозиторий на https://github.com/new, например `english-level-test`. Для GitHub Free используйте публичный репозиторий (в нём только код; не помещайте персональные данные).
2. Загрузите **все файлы этого архива** в корень репозитория (`Add file → Upload files → Commit changes`). В `firebase-config.js` должны быть ваши параметры Firebase. Пароли и секреты в GitHub **не загружайте**.
3. Перейдите в **Settings → Pages → Build and deployment**.
4. Выберите **Deploy from a branch**, затем `main` и `/(root)`, нажмите **Save**.
5. Сайт станет доступен примерно по адресу `https://USERNAME.github.io/english-level-test/`.
6. Кабинет преподавателя: `https://USERNAME.github.io/english-level-test/admin.html`.
7. Откройте тест, пройдите его с тестовым кодом и проверьте, что в кабинете появился результат.

## 3. Как пользоваться

- Ученик открывает страницу `index.html` (или корень сайта), вводит **код**, подтверждает ознакомление с условиями, отвечает на вопросы, выполняет Writing и нажимает завершение.
- При успешной отправке будет написано «Ответы успешно сохранены». Если возникла ошибка сети, следует нажать «Повторить сохранение» **без перезагрузки страницы**.
- Преподаватель открывает `admin.html`, входит по email и паролю, видит результаты, оценивает Writing по шкале 0–5 каждый и при необходимости Speaking по шкале 0–12. Итог `/36` и предварительный уровень обновятся после оценки.
- Кнопка **Скачать CSV** выгружает таблицу для Excel. CSV содержит результаты, **но не полные тексты Writing**; они доступны в кабинете.

## 4. Критерии

- Grammar: 10, Vocabulary: 6, Reading: 5, Listening: 5, Writing: 10; всего **36 баллов**.
- Writing 1 и 2: по 1 баллу за соответствие теме, грамматику, лексику, связность, соблюдение формата (0–5).
- **0–12** — A2 не подтверждён; **13–20** — A2; **21–27** — B1; **28–31** — B1+; **32–36** — B2 (требуется подтверждение устной речью).
- Speaking — отдельная диагностическая оценка из 12, не входит в /36.

## 5. Важные ограничения

- Сайт *не является официальным экзаменом CEFR*. Пороговые уровни примерные, а оценка Writing/Speaking субъективна. Автоматический уровень до проверки Writing носит ещё более грубый характер.
- Вопросы и ключи доступны в JavaScript браузера; ученик технически может их посмотреть или отправить сфальсифицированный балл. Firestore Rules ограничивают операции и чтение, но **не проверяют правильность баллов**. Для строго защищённого экзамена нужна серверная проверка (например, Cloud Functions) и аутентификация/индивидуальные ссылки.
- Listening выполняется с помощью **speech synthesis браузера** — качество произношения зависит от устройства, браузера и установленных голосов. Для стандартизированной проверки рекомендуется записать и подключить единый аудиофайл.
- Хранение детских ответов и идентификаторов требует соответствующего законного основания, разумного срока хранения и политики удаления. Рекомендуется выдавать ученикам случайные коды вместо ФИО, а соответствие кодов хранить отдельно в защищённом месте. Ученик должен знать, кто является ответственным за обработку и как запросить удаление результата.
- Текущие правила позволяют преподавателю читать все работы и удалять их через Firebase Console, анонимному ученику — только создать новую. Проверьте правила через Firebase Rules Playground или Emulator до публикации.
- Учётную запись преподавателя следует защитить сильным уникальным паролем. Открытая админ-страница сама по себе не раскрывает данные, но утечка преподавательского пароля даст доступ к ним.
- Firebase может иметь квоты и платные ограничения. Проверьте актуальные условия тарифов перед использованием.

## Проверка локально

ES-модули лучше запускать через локальный веб-сервер, а не двойным щелчком по HTML: `python -m http.server 8000`. Откройте `http://localhost:8000`. Для входа с localhost при необходимости добавьте `localhost` в Firebase Authentication Authorized domains.
